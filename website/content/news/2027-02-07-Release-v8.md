We are preparing arara version 8 for 7 February 2027, the start of TeX Live
2027 pretest. With this release, we are making Lua the default language for
rules and extending the project support introduced in version 7. We have also
worked on making build results and problems easier to follow in the terminal.

<!-- more -->

# Important changes

Please consult our [changelog](@/CHANGELOG.md) for a detailed view on all
changes and references to our issue tracker. This post is targeted at our
users and covers the most relevant changes.

## Updating from arara 7

arara now requires Java 21 or newer. Before updating an existing workflow,
read the [migration notes](@/news/2026-10-22-Migration-v8.md) for compatibility
changes and examples.

The supplied launchers handle the Java options and libraries needed to run
arara. If you launch the jar directly or embed arara in another application,
check the updated [installation instructions](@/manual/Deploying.md).

## Lua rules and configuration

All official rules are available in Lua. Existing directive comments still
select rules by name, so ordinary documents can use the new engine without
rewriting their directives. Custom rules and conditional expressions need a
migration to Lua; the migration notes explain the differences.

YAML/MVEL rules remain available through `--engine yaml` as a legacy engine.
Using them produces compatibility warnings, which can be disabled in the
configuration. Support for these rules will end in arara 9. YAML configuration
files and YAML directive parameters remain supported.

Lua configuration files can compute settings and paths. Configuration lookup
prefers a local file over a global one, and Lua over YAML within a directory.
Lua project specifications can be combined with other projects and ordinary
input files in one invocation, with dependencies determining the project order.

## Feedback from your builds

The plain console remains the default. An optional styled console adds task
frames, interactive terminal dialogs and progress indicators. Both layouts
report build outcomes and files left unprocessed after a failure. Dialogs run
in the terminal instead of opening graphical windows.

Diagnostic logs can use text or JSON Lines. They record the selected rules,
commands, timings and outcomes, together with configuration and runtime context.
JSON records let tools inspect a run without parsing console presentation.

French joins the available interface languages, and the new `upmendex` rule
supports multilingual Unicode indexes in both engines.

# The next steps

The refreshed website brings together the [quickstart](@/Quickstart.md),
[manual](@/manual/_index.md) and migration notes. Library users also have an
updated API reference alongside the published Kotlin artifacts.

During TeX Live pretest, please try your existing documents and custom rules
with arara 8. Report problems on our
[GitLab issue tracker](https://gitlab.com/islandoftex/arara/-/issues), including
a small example and the arara and Java versions used.

The transition to Lua does not include a native executable in this release.
arara continues to run on the JVM. We welcome feedback on the new Lua rules
and project support before considering further changes to the runtime.
